A cross-device clipboard that syncs your own devices over the local network, end-to-end encrypted, with sharing that is explicit and temporary.

The problem

Moving text between your own devices is still absurd.

You already copied it. The computer already has it. And yet.

Workaround 01

Email it to yourself

Open mail, compose, paste, send, switch device, open mail, copy again. Seven steps to move eleven characters.

Workaround 02

Message yourself

A chat thread with one participant, now permanently full of one-time passcodes and half-finished links.

Workaround 03

A notes app in the middle

Sync delay, a document you never wanted, and your clipboard content stored on someone else's server forever.

Every one of these is slower than the copy the user already made — and two of them keep a permanent record of something that was meant to last five seconds.

The promise

Three steps, and two of them already existed.

01

Copy, normally

Cmd + C on the laptop. No app to open, no button to press, nothing new to learn.

02

It travels directly

Encrypted, over the local network, to the devices you registered. Typically under two seconds.

03

Paste, normally

Cmd + V on the phone. The clipboard is simply already correct.

Set up once

Sign in, install the agent, approve the device. There is no second configuration screen.

Pause instantly

One switch on the device card. Sync stops in both directions, immediately.

Nothing is kept

Clipboard content is not stored on our servers, and local copies expire quickly.

The constraint that shaped the product

A browser tab cannot watch your clipboard.

This is not a limitation we can engineer around. It is the security model of every operating system, working correctly.

What people assume

  • “Just make it a website.”
  • A background tab polls the clipboard forever.
  • Mobile watches the clipboard invisibly.
  • Permissions are asked once and never again.

What the OS actually allows

  • A native background agent, installed deliberately.
  • Clipboard reads tied to focus and permission.
  • Mobile: user-triggered share and paste actions.
  • The web app manages account, devices and sharing.

ADR-002 — Native background agent. Never fake background behaviour with a browser tab or a hidden polling loop. Where a platform cannot do something silently, we ship the simplest supported alternative instead.

The security position

Discovery is not authorisation.

Being on the same Wi-Fi tells us a device exists. It tells us nothing about whether it may read your clipboard.

What we refuse to build

if sameSubnet: sendClipboard()

Trivial to snoop. No identity. No revocation. This is the design most LAN tools ship.

What we require instead

if authenticated and deviceIsRegistered and deviceIsAuthorizedForSession and peerIdentityIsVerified: sendClipboard()

Every device has a key

Ed25519. The private half never leaves the device, and is never logged.

Peers prove identity

A discovered device must demonstrate possession of its key before any payload moves.

Revocation is immediate

A removed device stops receiving. This is a tested behaviour, not a promise.

Hostile until proven

Every discovery response and every message is treated as untrusted input.

Explicit, temporary, and impossible to forget about.

Rule 01

Membership is explicit

A session has named members with roles. Nobody joins by being nearby.

Rule 02

Sessions expire

Short-lived by construction. Temporary sharing is actually temporary.

Rule 03

The state is always visible

The banner cannot be dismissed, and Stop sharing is always one click away.

Violet is reserved. In this product, violet means one thing only: someone outside your account can currently receive your clipboard. It is never used decoratively, so the signal cannot be diluted.

Design system

Colour carries the security model.

The hard problem in this product is not aesthetics. It is legibility of trust.

Blue — your devices
#2563EB
Product chrome and every normal interaction.
Violet — others can see this
#7C3AED
Only while a share session is live. Never decorative.
Red — irreversible
#E04640
Revoke, remove, end session. Not for form validation.

One vocabulary, three clients

Web, desktop and mobile render the same backend state identically — same colour, icon, label and sub-label.

Synced Paused Offline Revoked Live

Rules that block review

  • Green never means “same Wi-Fi” — only authenticated and authorised.
  • Never colour alone: every status carries an icon and a label.
  • The security signal must survive reduced motion.

Privacy

Clipboard content is sensitive by default.

It contains passwords, one-time codes, addresses and account numbers. We designed as if it always does.

What we log

device connected peer authentication failed payload rejected: too_large sync latency: 142ms

What never exists anywhere

clipboard = "password123" image = <raw bytes> token = "..."

No cloud archive

Clipboard history is not a server-side product feature in the MVP.

Previews are truncated

140 characters, one line. Images show as blurred thumbnails with dimensions.

Secrets stay masked

Content shaped like a key or token is masked until deliberately revealed.

Not in notifications

“Text copied from MacBook Pro” — never the text itself.

Frozen and pinned

Roadmap

Each phase is independently testable.

Phase 1 · now

Protocol

Domain types, clipboard watcher, local loopback sync, tests.

Phase 2

Two devices

LAN discovery, authenticated peer connection, security tests.

Phase 3

Account

Registration, device management, the web application.

Phase 4

Sharing

Share sessions, mobile integration, UX hardening.

Phase 5

Remote

Transport abstraction, optional relay for devices apart.

Why this order

The local experience has to be reliable before a remote path is worth building. Phase 5 changes the transport, not the event format — that is what the abstraction buys us.

What gates a phase

Tests pass, security cases covered, contracts unchanged or versioned, handoff written. A phase is not done because it compiles.
